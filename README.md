# This is not a notified trust list

It is development test material published by one project, for one modified wallet build, so that
software under development can be tested at all. If you arrived here looking for an EU trust list,
**this is not one and must not be used as one.**

## What is here

`lote/WRPACProviders.jwt` — a list of Wallet-Relying Party Access Certificate providers, in the
ETSI TS 119 602 form, signed as a JWS.

It contains **eight** trust anchors:

- the **seven** anchors carried forward, byte for byte, from the EUDI Wallet Reference
  Implementation's development list at
  `https://trustedlist.serviceproviders.eudiw.dev/LOTE/json/WRPACProviders.jwt`; and
- **one** of ours, `EDTP Development Access CA - TEST ONLY`, which is self-signed, notified by
  nobody, and trusted by nothing except a wallet we modified ourselves to trust it.

`lote/edtp-dev-access-ca.crt` and `lote/edtp-lote-signer.crt` are the two certificates, published
separately so that anyone can check what the list actually asserts without decoding the JWS.

`lote/PIDProviders.jwt` — a list of **PID Providers**, in the same form, built the same way: the
**seven** anchors carried forward byte for byte from
`https://trustedlist.serviceproviders.eudiw.dev/LOTE/json/PIDProviders.jwt`, plus **one** of ours,
`EDTP Development PID Provider CA - TEST ONLY` (`lote/edtp-dev-pid-ca.crt`). A PID signed under
that CA is **test data issued by a development platform**, not a PID: no Member State has notified
it, and only a wallet we modified ourselves (deviation WD-4) consults this list. It is signed by the
same `edtp-lote-signer.crt`.

`lote/EAAProviders.jwt` — a list of **non-qualified EAA providers** with exactly **one** anchor,
`EDTP Development Attestation Provider - TEST ONLY` (`lote/edtp-dev-eaa-provider.crt`, self-signed),
which signs this project's Power of X test attestations. Unlike the two lists above it carries
**nothing** from a notified list: for a non-qualified EAA there is none to extend, so the EUDI
development PubEAA list was used as a structural template only. It is read by the platform's own
verification engine, not by any wallet. Its service and list type identifiers are `urn:edtp:test:…`
values of ours, because the ETSI TS 119 602 identifier for this domain was not verified. Signed by
the same `edtp-lote-signer.crt`.

## Why it exists

Under Regulation (EU) No 910/2014 as amended, and ARF 3.0.0, a Wallet Unit accepts access
certificates only from Access CAs on lists **notified by Member States** — `AS-WP-06-005`
(`RPA_04`). That is the correct behaviour and this list does not change it for anybody: an
unmodified wallet has never heard of this URL and will never fetch it.

The intended route was to obtain a real access certificate from the EUDI reference Relying Party
Registration Service. That route is currently broken — its `POST /intended_use/create` reports
success and persists nothing, which makes both of its certificate endpoints unreachable — so there
is no certificate to test with. This list is the documented fallback, and it is deliberately
additive: the seven notified anchors are preserved so that a wallet carrying it still trusts every
real Relying Party, rather than only us.

## What a result obtained with it means

Less than a result from an unmodified wallet, and any honest report says so. A wallet configured to
consult this list is a **modified wallet**. It is not "the EUDI Reference Wallet", no conformance to
the ARF or to the Technical Specifications is claimed from it, and nothing here is fit for any
purpose beyond development testing of the software that publishes it.

## Provenance

Generated by `implementation/scripts/make-test-lote.mjs` in
[ssanchocanela/european-digital-trust-platform](https://github.com/ssanchocanela/european-digital-trust-platform).
The script, the reasoning behind every field, and the record of the Registrar defect that made this
necessary are all in that repository.

The seven copied anchors go stale: the reference lists roll over roughly every six months, and last
did on 10–11 September 2026. If this list's `NextUpdate` has passed, it has not been regenerated and
should not be trusted even for testing.
